# 月報コメントの数値突合テスト（Phase5 Task 5-5）

生成された月報コメント内の全数値が、`v_variance` の値と一致することを確認する。

## 仕組み

- コメント内の数値には `[[数値|部門コード|製品コード|列名]]` の注記を付ける（部門集計は製品コードを `*`）。`--plain` を付けると注記を外した読み用テキストを出力できる。
- [validate_comment.py](validate_comment.py) が `v_variance` の生の列を読み取り専用サービスアカウントで取得し、万円・%への換算を Python で独立に再計算して、コメントの数値と突合する。テンプレートのクエリA・Bの結果は使わない。
- 注記のない数値（製品コード・順位・年月などを除く）が残っていれば失敗にする。
- `variance_*` と `cost_yoy_*` は符号表記（超過は `+`、未達は `-`）も検査する。

## 実行方法

前提: Python、gcloud/bq CLI。鍵は環境変数 `GOOGLE_APPLICATION_CREDENTIALS`、無ければリポジトリの `.mcp.json` から読む。実行のたびに一時的な gcloud 設定ディレクトリを使うため、普段のログイン状態は変わらない。

```
cd tests/output_validation
python validate_comment.py comments/2026-08.md
```

## 結果（2026-09-20実施）

| 対象月 | 突合した数値 | 失敗 |
| --- | --- | --- |
| 2026-06 | 28件 | 0件 |
| 2026-07 | 28件 | 0件 |
| 2026-08 | 26件 | 0件 |

3か月分（部門別コメント）のすべての数値が `v_variance` の値と一致した。

### 検知能力の確認

わざと誤りを混ぜた2026-08のコメントで、次の4種類をすべて失敗として検知することを確認した。

- 数値を1桁書き換える（`+23.3` → `+23.4`）
- 注記を外して数値を残す
- 符号を落とす（`-52.2` → `52.2`）
- 別の列の値として注記する（直接材料費比率を不良率として注記）

## 限界

- 数値以外の記述（「標準並み」などの評価、「OVER_BUDGETのみ超過と書く」といったルール順守、要因仮説の妥当性）は機械検証していない。人が読んで確認する。
- 注記はコメント作成者が付けるため、注記の対応先を誤っても値がたまたま一致すれば通る。ただし注記のない数値は失敗になるので、注記なしで数値を紛れ込ませることはできない。
- 3か月分（2026-06〜08）のみ。月報の運用開始後は、月次で実施するか、抜き取りで確認する。
- 前年データなしの行（`prior_year_cost_man` が0、`cost_yoy_pct` がNULL）はワースト10に入ることがある。コメントは前年比に言及せず、「前年データなし」と書く（テンプレートの規則どおり）。
