# 原価管理App 構成ガイド

2026-11-15 時点

## 概要

原価管理Appは、工場の売上・生産・原価データを月ごとに BigQuery に集め、予算や前年との差（差異）を見える化するしくみです。独立したサーバーは持たず、Google のサービス（Drive・スプレッドシート・Apps Script・BigQuery・Looker Studio）と Claude API を組み合わせて作られています。

やることは大きく3つです。

1. **集める**: 現場の Excel をアップロードし、整えて BigQuery に入れる
2. **計算する**: BigQuery のビュー `mart.v_variance` で、年月×製品ごとの原価・予算差異・前年差異を出す
3. **使う**: ダッシュボードで見る、月報コメントを作る、閾値を超えたら通知する、日本語の質問で検索する

## 全体構成

このアプリは「集める」「計算する」「使う」の3層でできていて、中心にあるのは BigQuery のビュー `mart.v_variance` です。

```
① 集める（GAS・Drive）
   [01 ファイル登録] ──▶ [02 中間S生成] ──▶ [03 DataRoad]
    Excel→CSV（Drive）    CSVを検証しstg_*へ    シート→BigQuery
                                                     │
        ┌────────────────────────────────────────────┘
        ▼
② 計算する（BigQuery）
   [master / history] ──▶ [mart.v_variance] ──▶ [explore.v_cost]
    台帳9表と月次実績       年月×製品の原価・差異     検索用・日本語列名
                                  │                      │
        ┌─────────────────┬───────┴─────────┐            │
        ▼                 ▼                 ▼            ▼
③ 使う（画面・通知）
   [Looker Studio]   [月報コメント]      [04 閾値アラート]  [05 自然言語検索]
    3ページの画面      Claude Code＋MCP    毎月5日 Chat通知   Claude APIで条件化
```

使う層の4機能のうち3つは `v_variance` を直接読み、自然言語検索だけはそこから原価系の列を抜き出した `explore.v_cost` を読みます。Claude が関わるのは月報コメントと自然言語検索の2か所です。

| 使う技術 | このアプリでの用途 |
| --- | --- |
| Google Apps Script（GAS） | 取込処理、アラート、Web アプリ（01〜05） |
| Google Drive・スプレッドシート | CSV の置き場、取込設定、中間テーブル |
| BigQuery | データの保管と集計（`master`・`history`・`mart`・`explore`） |
| Looker Studio | ダッシュボード |
| Claude（API・Claude Code） | 月報コメント、質問文の条件化 |
| Google Chat | アラートの通知先 |
| Node.js（clasp）・Python | GAS の反映、手元テスト |

## 主な機能

機能は7つで、すべて「集めたデータを `v_variance` にまとめ、そこから使う」という形でつながっています。

| 機能 | 誰が・いつ使うか | 中身 |
| --- | --- | --- |
| ファイル登録 | 担当者が毎月 | Web 画面で Excel と対象月を選んでアップロード。保存先は「取込_設定シート」で管理し、コードを直さずに種類を追加できる |
| 取込前処理（中間S生成） | GAS を実行 | 列名の対応付け、必須チェック、日付や数値の型をそろえる。不正な行は「取込エラー」シートへ。同じ月を再取込しても重複しない（洗い替え） |
| BigQuery ロード（DataRoad） | GAS を実行 | マスタ9表は全件入れ替え、履歴は未登録の月だけ追加。指定した1か月のやり直しもできる |
| ダッシュボード | 管理者が随時 | Looker Studio の3ページ（サマリー／切り口別／比較分析）。接続先は `v_variance` のみ |
| 月報コメント生成 | 月次で Claude Code 上で | 部門ごとのワースト10製品と部門合計を SQL で取り、Claude が「主要差異→要因→次月アクション」を書く。数値はテストで突合する |
| 閾値超過アラート | 自動（毎月5日9時台） | 部門内ワースト10以内で予算超過、かつ差異率30%以上・差異額30万円以上の製品があれば Google Chat に1通だけ送る |
| 自然言語検索 | 社内の利用者が随時 | 「先月の第二工場の原価を製品別に」などの質問を条件に変換し、利用者が確認してから集計する。対象は原価系の指標7件 |

## データの流れ

毎月の処理は「Excel → CSV → 中間シート → BigQuery → ビュー → 各機能」の一方向です。途中で不正データを落とし、同じ月を何度取り込んでも結果が変わらないように作られています。

### 月次の取込と分析

1. **アップロード（01）**: 担当者が Excel を登録。先頭シートが CSV（`{ソース名}_{対象期間}_{登録日時}.csv`）になり Drive の取込フォルダへ
2. **整形（02）**: 「設定シート」の定義どおりに検証し、正常行を `stg_*` シート、異常行を「取込エラー」へ。処理済み CSV は別フォルダへ移動
3. **ロード（03）**: `stg_*` を BigQuery の `master.*`（製品・顧客・工場など9表）と `history.*`（売上・生産・原価・予算など）へ
4. **集計（v_variance）**: マスタと履歴を結合し、年月×製品ごとの原価・予算差異・前年差異・部門内ワースト順位（`cost_budget_variance_rank`）を計算。工場と顧客は製品マスタ経由（1製品 = 1工場・1顧客）
5. **利用**: Looker Studio、月報コメント、閾値アラートがすべて `v_variance` を読む。ワースト N の定義もこの順位列で共通

### 自然言語検索の1回の流れ

1. 利用者が質問を入力する
2. GAS が質問文と指標カタログを Claude に送り、**条件 JSON**（指標・期間・絞り込み・切り口・比較）を受け取る。Claude は SQL を書かない
3. GAS が辞書で「第二工場」などを正式名称に、「先月」を具体的な月に確定し、dry run で読み込み量を見積もる
4. 画面に条件チップを出し、利用者が確認・修正して「実行」
5. GAS が条件を再検証し、許可リストとパラメータで SQL を組み立てて `explore.v_cost` を集計。結果は Claude を通らず画面へ。質問と結果は `explore.nl_search_log` に残る

## 開発・運用のポイント

最初に押さえるルールは「数値は BigQuery が計算し、Claude は解釈だけを担う」です。

- **ビューが正**: 列の定義は `sql/03_v_variance作成.sql` を見る。ダッシュボードも生テーブルではなくビューにつなぐ
- **年月で必ず絞る**: `v_variance` は読み込み範囲の削減が保証されないため、`target_month` の指定なしの全期間クエリは禁止
- **Claude への送信範囲**: `requirements.md` で決めたデータだけ。自然言語検索では質問文とカタログだけで、データ行は送らない
- **GAS の反映**: 01〜05 とも手元で編集して clasp で反映する（01 は `npm run gas:push:upload`、02-03 は `npm run gas:push:import`、04 は `npm run gas:push`、05 は `npm run gas:push:nl`）。push はエディタ側の内容を上書きするので注意
- **環境ごとの値は `config/env.json` だけに書く**: プロジェクト ID や各種 ID をコードや SQL に直接書かない。SQL・プロンプト・カタログでは `{{PROJECT_ID}}`・`{{LOCATION}}` と書き、`npm run env:render` で実際の値に置き換える（詳しくは下の「環境ごとの設定」）
- **自然言語検索の設定**: 正は `nl_search/catalog/*.json`。`カタログ_自動生成.gs` は手で直さず、`npm run test:nl` で作り直す
- **テスト**: `npm run test:nl`（検索の辞書・SQL 組み立て）、`python validate_comment.py`（月報コメントの数値突合）
- **秘密情報はリポジトリに入れない**: API キーや Webhook URL はスクリプトプロパティ、BigQuery の鍵はリポジトリ外のフォルダ
- **Git**: 変更ごとにコミットして push（`CLAUDE.md`）

### 環境ごとの設定

顧客ごとに違う値は `config/env.json` に集め、ほかのファイルはどの環境でも同じ内容にしています。新しい顧客の環境を作るときに直すのは、原則としてこのファイルだけです。

| 生成されるもの | 使い道 |
| --- | --- |
| `gas/*/環境設定_自動生成.gs` | 各 GAS が読む ID（`const ENV`）。各 GAS の設定（`CONFIG` など）は、ここから値を読む |
| `gas/*/.clasp.json` | clasp の反映先 |
| `.mcp.json` | Claude Code から BigQuery を読む設定 |
| `build/sql/*.sql`・`build/prompts/*.md` | 実際のプロジェクト ID を入れた SQL。BigQuery のエディタにはこちらを貼る |

- 値を変えたら `npm run env:render` を実行する。`npm run gas:push`・`gas:push:nl` は、反映の前に自動で実行する。
- 新しい環境は、`config/env.example.json` を `config/env.json` にコピーして値を入れる。「ここに」で始まる値が残っていると、生成はエラーで止まる。
- Web アプリ（01・05）は、反映しただけでは公開中の版が変わらない。`clasp update-deployment` で新しい版にする（手順は `gas/README.md`）。
- 生成物は手で編集しない（次の生成で上書きされる）。

### 用語集

| 用語 | 意味 |
| --- | --- |
| GAS（Apps Script） | Google のサービス上で動く JavaScript。Drive やスプレッドシートを操作できる |
| clasp | GAS のコードを手元と Apps Script の間でやり取りするコマンド |
| BigQuery | Google のデータウェアハウス。SQL で大量データを集計する |
| マスタ／履歴 | マスタ = 製品や工場などの台帳。履歴 = 毎月の売上・生産・原価などの実績 |
| ビュー | 保存された SQL。テーブルのように読めるが、読むたびに計算される |
| 差異 | 実績と予算（または前年）の差。予算より原価が多いと「超過」 |
| 洗い替え | 同じ対象の古いデータを消してから新しいデータを入れること |
| MCP | Claude が外部のツール（ここでは BigQuery）を使うための接続のしくみ |
| dry run | 実際には実行せず、読み込むデータ量だけを見積もること |
